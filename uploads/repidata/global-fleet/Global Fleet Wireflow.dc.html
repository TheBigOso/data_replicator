GLOBAL LOG
global.out — one log of every fleet system
The single org-wide record: every fleet system appends here. Each fleet merges its virtual fleets, each VF merges its streams, connections, jobs, events and alerts — so one tail shows everything happening anywhere, time-ordered, each line prefixed with its fleet/vf/stream origin.

09:14:00 stream-corp/vf-fin/gl-feed: integrate cycle 512 rows

09:13:57 stream-west/vf-erp/erp-fanout: checkpoint advanced

Capture Integrate Latency Errors ⇱ Overlay
Docked 240px panel at the bottom of the console — the executive "heartbeat" view. Filter chips narrow to error/latency lines across all systems at once; follow mode tails live; ⇱ Overlay reopens it in the floating viewer alongside any fleet/VF/stream log tabs for side-by-side comparison. Read-only like the rest of the console: acting on a line means following it into its fleet.
Hierarchy: <stream>.out → <vf>.vf.out → <fleet>.fleet.out → global.out — each level merges everything below it, time-ordered. global.out is the top: the union of every fleet's log, hence of every VF, stream, job, event and alert in the organization.

DRILL-DOWN · WHERE EACH CLICK LANDS
• Open fleet → Fleet view: VF list · fleet log · fleet timeline
• VF row / Switch → VF dashboard: needs-attention · KPIs · streams · VF log
• Triage: stream error → stream dashboard, error surfaced
• Triage: CPU / memory / IO → connection detail, Server health panel expanded
• Triage: delivery failure → the alert rule's log
• ⇱ Overlay → floating log viewer, global.out tab added
Then: the target fleet/VF becomes the working context — the console itself never mutates anything. Back-link "← Global fleet manager" returns here.
