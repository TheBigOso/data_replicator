Global fleet console · ⚙ Global Admin
The Global Fleet console is read-only; this surface is where the top level edits. Header shows the capability note: "Global Admins can edit any account, create fleets, and edit any connection, table, alerts, jobs, and events — everywhere."

GATE · SUPERADMIN / SYSADMIN
Repository-level grant required
Without it the tree entry renders 🔒 and clicking shows a toast: "Global Admin requires a repository-level grant (SysAdmin or SuperAdmin). Ask a SysAdmin on Admin → Permissions."
Hierarchy: the same Admin screen also opens at Fleet and VF level with narrower scope — this flow is the global level; editing is strictly downward.

TAB 2 · CURRENT HUB
One VF's card, properties, tuning
• hub selector ▾ picks which VF the tab shows
• Freeze/Unfreeze — stops scheduler + all jobs, preserves state; frozen banner warns capture may not resume after source logs are cleared
• New hub · ⋯ menu: export definition, import…, save snapshot…, delete
• hub card: state, creator, access · properties list
• Statistics tuning: granularity/cycle selects + retention estimate (applies after the job restarts)
At global level any hub is selectable; Fleet/VF levels see only their own.
→
TAB 3 · USERS
Every account in the system
• sortable: name · email · auth · status · last active · created
• actions: Edit · Reset credential · Enable/Disable
• Add user (inherits every All Users grant)
• multi-select → delete
• service accounts badged; sign-in is email-based, no usernames
Accounts only — access lives on the next tab. Disable revokes nothing.
Detail flow: the full Users + Permissions mechanics have their own diagram — Users Permissions Wireflow.
→
TAB 4 · PERMISSIONS
Every grant, editable
• one row per grant attachment (user × scope × tier)
• global level edits everything — including repository grants no lower level can touch
• Add access: principal → scope → tier
• Revoke per row; only self-SuperAdmin is locked (no self-lockout)
Tiers: SuperAdmin · SysAdmin · HubCreation · ReadStatistics · FleetViewer (repository) — HubOwner · ReadWrite · ReadExecRefresh · ReadExec · ReadOnly (hub).
DIALOG · NEW FLEET
Enroll a system
Fields: fleet name (e.g. streamsrv-defense) · division/organization.

A fleet is a hub-server registration — enrollment produces its URL and mTLS identity; virtual fleets are created inside it afterwards. The creator becomes its first Fleet Admin.
Gate: only Global Admins create fleets. Name is required.
→
OUTCOMES · ALL LEDGER-RECORDED
• new fleet → appears in the Global Fleet matrix and the tree; creator holds Fleet Admin
• user/grant edits → visibility, Switch buttons, admin entries, and the FleetViewer gate re-evaluate immediately
• every create, edit, grant, revoke, enable, disable is an event in the ledger
• back to the console: ← Global fleet (read-only again)
