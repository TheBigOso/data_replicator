BRANCH B · ⚙ FLEET ADMIN
The middle tier of the three-level admin model
Same admin screen as Global and VF admin, scoped down: "Fleet Admins can edit fleet admins, manage/update/create virtual fleets in this fleet, and edit any connection, table, alert, job, and event — within this fleet."
Users Permissions Virtual fleets Fleet settings
Users
Accounts whose grants land in this fleet. Create / disable / reset auth; service accounts flagged separately. Cannot create accounts scoped outside the fleet — that stays Global Admin.
Permissions
The grant table filtered to streamsrv-corp and its VFs. Grant HubOwner / ReadExec / ReadOnly at fleet or VF scope. FleetViewer and SysAdmin are not grantable here — repository scope is Global Admin's.
Virtual fleets
Per-VF row actions: freeze / unfreeze the scheduler, snapshot, export definition, delete (typed confirmation), and stats-retention tuning. Freeze holds capture positions — it never drops state.
Fleet settings
Display alias, sidebar pin default, alert-manager cycle, retention windows. The enrollment id and hub URL are read-only — changing those is a re-enrollment, done from Global Admin.
Gate: the ⚙ button only renders for HubOwner-at-fleet-scope, SysAdmin, or SuperAdmin. Everyone else never sees it — no disabled-button teasing.
BRANCH C · MODAL · NEW VIRTUAL FLEET
Create a logical hub inside this fleet
A virtual fleet is its own repository namespace on the same hub server: own streams, connections, jobs, users, and log. Creating one is cheap and reversible; it starts empty and inert.

RULES THIS PAGE HOLDS TO
· Display aliases never leak into ids, log file names, scopes, or events.
· Actions you cannot perform are absent, not disabled.
· Triage ordering is deterministic — rows never reshuffle on a live tick.
· Every count on this page is derived from visible VFs only.
· Switching VF changes context everywhere at once: header, tree, and all downstream screens.
