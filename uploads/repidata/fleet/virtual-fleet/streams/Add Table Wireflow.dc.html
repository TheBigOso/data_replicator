3 · STOPPED AND REMOVED

RE-ADD LATER
The table reappears in the Add-table catalogue — registering it again is the standard add flow, and the initial load is a fresh refresh (or a repair-scope refresh if the target rows were kept).
Gate: removal is scoped per stream (stream·identity) — removing a table from a duplicate leaves the original's registration intact. Cancel / ✕ in the dialog stops nothing.
BRANCH · what the catalogue flags (registrable, but warned — the guardrail the product sells)
No primary key
Apply would match on all columns — slow and unsafe on updates/deletes. Fix: add a key or choose a unique index before heavy use.
No supplemental logging
The source can't produce before-images — capture registers but can't emit full change rows until ADD SUPPLEMENTAL LOG GROUP (or the dialect's equivalent) runs. The table-detail DDL pane shows the exact statement.
Already registered
Hidden from the catalogue entirely — the list is only what can still be added to this stream; a duplicate stream keeps its own list.
Flag propagation
Warnings travel: picker row → review list → "flagged" field on the DEFINITION CHANGE event, so the ledger names what needed attention at registration time.
