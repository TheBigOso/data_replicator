One scope rule. Connections belong to the virtual fleet, not to a stream — they sit beside Jobs and Events. Opened at VF level: every connection its streams use, plus unattached ones. Opened from a stream: just that stream's source and target.
So a count in the Global Fleet console always matches what the screen it opens contains.

SORT · FILTER · PERSIST
How operators find one row
Every header sorts. Click to sort, click to reverse, ▲/▼ on the active column. Default is Connection descending, indicator visible on load — the sort state is never implicit.
Numeric columns sort numerically. Heartbeat and Streams — a 14-minute-stale agent must not sort between 1s and 2s because "1" precedes "2".
Per-column filter boxes. Substring, AND across columns, applied immediately. The Connection filter also matches the role, so typing target narrows to targets without a separate control.
No match = explicit empty state, never an ambiguous blank area.
Persistence split. Column visibility and sort are per user, restored at sign-in. Filters are session-only — a transient act of looking, not a preference.

① AGENT CARD
How the hub reaches the endpoint
Connect via agent
Enrolled binary near the DB, over mTLS. Less network cost, distributed CPU, and capture directly from the logging system.
Agentless
Hub connects directly. Zero footprint — all capture load and network cost land on the hub.
Agent mode fields: mode · binary version · enrollment method · agent host · agent port · heartbeat age · regular vs RAC-cluster.
Test agent connection checks reachability, latency, mTLS handshake, certificate verification, and hub/agent version match.
Configure agent service: service account · spool directory · log level · upgrade ring.
Certificate panel: pinned fingerprint · rotate certificate (picked up on next heartbeat, old one honored for a grace period) · re-issue enrollment token (single-use, short-lived, ledgered).
Agentless mode states plainly that the hub connects directly, with the reachability-probe age instead of a heartbeat.
Switching to agentless is a visible change: the Agent column and the card both re-render to agentless · hub-direct.

BRANCH A · WIZARD · NEW CONNECTION
Five steps, not one dense form
Each step confirms before the next opens; completed steps collapse to a one-line summary with an Edit action. A persistent rail carries the name, description, and progress — the operator always knows what they have committed to and what remains.
1 · Select location type — every supported platform, filterable All / Sources / Targets, each stating the roles it can take. The choice seeds the default port and constrains every later step.
2 · Select agent connection — agent vs hub-direct with each mode's cost stated · host and port · regular vs RAC cluster · test agent connection · configure agent service · certificate state · authentication method.
3 · Configure location connection — platform-shaped: Oracle asks ORACLE_HOME and local-SID or TNS; others ask host, port, database. User and password with the vaulting statement.
4 · Configure capture / integrate — role (only what the class supports) and method, with the class's options and the same configuration-time cross-validation as the edit dialog.
5 · Stream membership OPTIONAL — save unattached (the default) or attach to streams in the current VF now.
A connection exists on its own. Membership is a separate, optional act — defining a database before any stream needs it must not force you to invent one.
A name is required and unique. It is how every stream, job, and event refers to the connection. A duplicate is refused at creation, not after.
What you entered is what shows. Every collected value is stored and rendered. No derived defaults stand in for blanks.
Exit: the connection enters as Enrolling with no heartbeat until its first one arrives. The confirmation states whether it was attached to a stream or saved unattached; an unattached connection says so plainly on its detail screen, with an action to attach it later.
BRANCH B · THE THREE EDIT DIALOGS
One shared contract
Agent · Database connection · Capture/Integrate. Each opens from its card's Edit action, and all three behave identically.
State the trade-off inline. Choices are cards with consequences written on them, not bare toggles.
Validate against the capability matrix at configuration time — rather than accepting anything and failing at job runtime.
Test connection before saving — a checkbox, checked by default, that can be unchecked.
Every save is ledgered. Who, when, what changed — in the event ledger and the VF log.
Saving untested is legitimate. An operator configuring a database that is down for maintenance must be able to record the configuration. The product allows it, says so in the confirmation, and defers validation to the next heartbeat or capability check.
BRANCH C · TEST CONNECTION
One action, staged results
Available from the list row, the detail header, and inside every dialog. It reports per stage, so a failure names the layer that failed rather than "could not connect".
✓Network reachability + latency
✓mTLS handshake + certificate verification
✓Hub / agent version match
✓Database authentication
✕Capture privilege check — missing SELECT on V$LOG
The outcome and its age populate the Last test column and the status pill, and the run is written to the event ledger like any other action.

RULES THIS SCREEN HOLDS TO
· Connections belong to the VF, never to a stream.
· Credentials are vaulted on the hub — never on agent disk or in logs.
· Roles are constrained by the capability matrix, not asserted.
· Blank reads as blank; no derived defaults stand in for empty fields.
· Saving untested is allowed, stated, and deferred — never silently "OK".
· Column setup persists per user; filters are session-only.
